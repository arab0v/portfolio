Building With AI Is Not All Rainbows

2026-09-24 · ai-workflow, nestjs, adminjs, keycloak

An honest look back, not a victory lap. The point is what the mistakes forced us to fix, not how many there were.

Everyone posts the highlight reel. "Shipped X in Y weeks with AI." Cool. Nobody posts the 71 times they had to hit stop because the agent confidently built the wrong thing, or the same bug it brought back after being told how to fix it.

So this is the other side of it. I did ship Rezefy's admin portal in under 3 months with an AI agent doing real work — but almost none of it went the way those timeline posts make it sound.

The numbers that never make the post

Going through the agent logs for just rezefy-admin: 98 sessions between late August and late September, 373 prompts from me, around 14,000 tool calls. Sounds like a smooth operation.

Here's the part that gets left out: I hit stop on it 71 times, spread across 36 of those 98 sessions. Not because it was slow — because it went the wrong way, guessed a field name instead of asking, or built the wrong thing completely. The posts bragging about "1000x productivity" never mention that number.

The bug that kept coming back

AdminJS record actions have one rule: when a handler changes a record and returns inline, it has to return record.toJSON(currentAdmin) — not a hand-built object. The agent wrote the wrong version. I fixed it. Moved to the next resource. It did the exact same thing again in the next one.

That's the thing nobody tells you about these tools: it doesn't take a fix from one file and use it in the next one. It fixes the exact spot you pointed at, then falls into the same trap in the next file like nothing happened.

What actually fixed it — not better prompts

Every one of these got fixed the same way: the moment I caught it, I wrote the pattern into a skill file the agent reads before it touches the code. Not a note to myself. A hard rule.

That file is now 604 lines across 17 sections, and every line is a mistake the agent made at least once. The early sessions, before the file existed, were rough. Constant re-explaining. By the last few weeks most of it was right on the first pass — not because the model got smarter, but because the rule was already written down instead of living in my head.

The boring, honest version

Building with AI isn't a cheat code. What actually happened at Rezefy:

  • A couple of days looking at admin frameworks — AdminJS won because it had a working Sequelize adapter, and that's the ORM our monorepo runs on. No magic, just a compatibility check.
  • Auth was locked down first — role-based permissions, Keycloak, Redis sessions, kill-everywhere — before a single admin screen existed. A broken login is about the worst thing that can happen. A broken button is just Tuesday.
  • A couple of days on the ESM/CommonJS fight (AdminJS v7 vs. CommonJS-only NestJS) that had nothing to do with our actual product. Wrote that one up separately.
  • The agent kept the server side following my patterns, with my review. Frontend I gave it more room. On purpose, not blind trust.

The part that's actually true

Yes, we shipped fast. 25 resources, 100 components, ~72k lines of admin code. But "AI built it" isn't the real story. It's closer to this: I spent three months training a junior who never sleeps and forgets everything between sessions, and writing things down was the actual job.

If you're starting a project expecting rainbows, you'll spend your first few weeks frustrated. Expect the interruptions. Expect the same bug twice. Set up the skill file on day one, not after you're already tired of repeating yourself.
